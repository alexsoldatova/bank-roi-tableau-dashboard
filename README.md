# Окупаемость банка

Воспроизводимое решение тестового задания на аналитика данных: проверка клиентской активности, когортная модель, юнит-экономика и сценарный график окупаемости от среднего остатка.

## Главный вывод базового сценария

- Текущая база из 100 000 активных клиентов приносит 45 млн руб. в месяц до расходов на новое привлечение: `100 000 × (1 000 - 500) - 5 млн`.
- Следовательно, банк уже операционно прибылен при заданных вводных.
- Отдельно оценен устойчивый поток новых когорт. При расходах на обслуживание только в активные месяцы и среднем остатке 0 руб. один привлеченный счет дает 2 367 руб. маржи после CAC на наблюдаемом 29-месячном горизонте.
- Для покрытия постоянных расходов только новым потоком требуется 2 113 новых клиентов в месяц.
- LTV до CAC в базовом сценарии без дохода на остаток — 7 367 руб.; CAC окупается за 18 месяцев.
- 122 клиента (0,61% выборки) открыли счет повторно; всего обнаружено 125 повторных счетов.

Это два разных управленческих вопроса: состояние действующего банка и окупаемость acquisition engine. В дашборде они показаны раздельно.

```bash

pip install -r requirements.txt
python scripts/build_tableau_data.py
```

## Методология

Единица анализа — счет `CLIENT_ID + OPEN_DATE`, поскольку один клиент может открыть счет повторно.

Для каждого месяца жизни счета `t`:

```text
eligible_t = счета, которые при дате открытия могли дожить до t к концу наблюдения
survival_t = open_accounts_t / eligible_t
active_probability_t = active_accounts_t / eligible_t
```

Так молодые, еще не успевшие дожить до поздних месяцев, не занижают кривую. Ожидаемые активные и открытые месяцы — суммы соответствующих вероятностей по наблюдаемому горизонту.

Базовая маржа одного привлечения:

```text
LTV = Σ(active_probability_t × fee)
    + Σ(active_probability_t × average_balance × annual_yield / 12)
    - Σ(service_probability_t × service_cost)
    - CAC
```

В базовом сценарии `service_probability_t = active_probability_t`. В альтернативном сценарии стоимость обслуживания начисляется во все открытые месяцы: `service_probability_t = survival_t`.

```text
required_new_clients = CEILING(fixed_cost / LTV)
```

Если LTV неположительный, окупаемость недостижима в пределах наблюдаемого горизонта.

## Ограничения

- LTV усечен фактически наблюдаемыми 29 месяцами и является консервативным для долгоживущих счетов.
- Доход на остатки начисляется только в активные месяцы; это явное модельное допущение.
- Датасет является рандомизированной выборкой, поэтому денежные оценки масштабируются через предоставленную текущую базу, а не через 20 000 клиентов выборки.
- Закрытие определяется как последний наблюдаемый месяц раньше мая 2026 года.

Инструкция по сборке визуализаций: `docs/tableau_build_guide.md`.

Готовый переносимый workbook создается в `outputs/bank_roi_tableau_public.twbx`.

В верхней части Tableau добавлен единый фильтр «Период отчёта». Он синхронно ограничивает когортную heatmap и динамику активной базы через общую группу фильтра. Показатели юнит-экономики рассчитаны на полном доступном горизонте и поэтому не пересчитываются от выбора месяца. Дробные значения выводятся с точностью до двух знаков, а подписи активности по возрасту счёта — до одного знака; на линейных графиках включены подписи значений.
